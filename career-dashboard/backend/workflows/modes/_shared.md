# Shared workflow rules

## Sources of truth

Read AGENTS.md, the selected profile's data/config/profile.yml, data/context/evidence.yml, source library and unresolved questions. The registry and citations govern candidate claims; a LaTeX template is rendering code, not evidence. The profile database owns all job status and history. Never edit generated tracker projections directly.

## Job review

Use the person's editable target roles and verified market. Check the exact employer or ATS posting, title, location, full description, application route, work authorization, required experience and hard requirements. A bare careers homepage is not a verified posting. Unknown authorization requires a question before eligibility-dependent work. Deduplicate by exact URL or requisition and preserve all recorded application dates and outcomes. Silence never means rejection or ghosting.

## Resume work

Map each role requirement to stable evidence IDs, distinguishing professional, academic and proposed work. Use the job's market-specific paper and the active profile's page, section and project contract. Select only registered resume-ready projects. No filler or invented metrics may be added to meet a page target. Compile, inspect each preview page, and run the resume validator. Save a JD snapshot, evaluation, research, evidence map, LaTeX, PDF, preview and QA together. An artifact passes only if its provenance, layout and claims pass; job fit and requirement coverage are separate decisions. No application or outreach is sent without explicit authorization.
